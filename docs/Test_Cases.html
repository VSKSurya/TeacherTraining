How to use

Use the section index, search test IDs or text, and record status plus actual results in each case row. Statuses and notes save in this browser. Use Export results to download a CSV backup. Clear progress resets the local execution record. Print / Save as PDF produces a clean paper copy.

00 CORE TEST JOURNEYS

Use the step controls or select a node to walk through the key end-to-end flows.

›››
Step 1 · Open sign in

Open /login signed out. Confirm the identity and password fields, required markers, and support links appear.

Step 2 · Enter credentials

Use a seeded Demo1–Demo8 account and the shared demo password. Check casing and whitespace behavior where relevant.

Step 3 · Validate account

Submit valid, invalid, unknown, and inactive account combinations. A failed attempt must not create an authenticated session.

Step 4 · Load role screen

After successful sign in, verify the correct dashboard, sidebar, user identity, and direct-route permissions for that role.

›››
Step 1 · Find batch

Open /register and enter the shared batch code. A matching batch should display its training and registration details.

Step 2 · Check eligibility

Check registration state, date window, and capacity. Closed, expired, not-yet-open, or full batches must not accept a request.

Step 3 · Submit request

Submit a name and at least one contact method. Duplicate requests for the same batch are rejected.

Step 4 · Review request

Confirm the request is pending review and appears for an authorized registration operator. Submission alone does not confirm a place.

18 17. Not currently verifiable from the UI alone

  • Password reset delivery is not implemented by the Forgot password control; it currently shows an informational message.
  • Trainee ID recovery requires VITE_TRAINEE_RECOVERY_API and a functioning OTP service. Without it, recovery should show the configuration message.
  • The sidebar includes Assessments and Certificates labels, but only the /assessments route is wired in the current app; no standalone certificates route is registered.
  • Feedback Report navigation should be checked against the rendered menu destination because the app/manual describe the feedback report route/menu differently.
  • Role data is persisted in browser local storage for this demo app; these cases do not establish server-side identity or authorization guarantees.
